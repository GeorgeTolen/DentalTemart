# Temart — многоклиниковая CRM для стоматологий

CRM для сети стоматологических клиник: календарь записей, карточки приёмов,
пациенты, врачи и их график, личные кабинеты. Каждая клиника — изолированное
пространство. Backend — REST API на Go + PostgreSQL, фронтенд — React (Vite),
который в продакшене раздаётся тем же сервером.

## Роли и вход

- **Администратор платформы (superadmin)** — владелец всей системы. Отдельный
  вход (`Вход для администратора платформы`). Управляет клиниками, создаёт их
  владельцев, видит сводную статистику по всем клиникам. Не привязан к клинике.
  Дополнительно может: заводить других администраторов платформы (вкладка
  «Администраторы платформы»), менять собственный пароль, смотреть и сбрасывать
  учётные записи любой клиники (кнопка «Учётки») и открывать данные клиники
  **только на просмотр** (кнопка «Открыть» — режим поддержки).
- **Владелец клиники (owner)** — полный доступ в рамках своей клиники: сотрудники,
  врачи, пациенты, записи, прайс услуг, финансы, отчёты, архив.
- **Менеджер (admin)** — то же, что владелец, кроме управления учётными записями.
  Прайс и финансы ведёт наравне с владельцем.
- **Врач (doctor)** — **видит** расписание всей клиники и всю общую базу пациентов
  (включая карточки и медкарты, заведённые другими клиниками платформы), но
  **менять** может только свои приёмы. Деньги — прайс, стоимость приёма, выручка —
  врачу не показываются вовсе. Свой профиль и пароль ведёт в личном кабинете.

У каждой роли есть **личный кабинет** (кнопка внизу бокового меню): у врача —
профиль, график и приёмы на сегодня, у владельца и менеджера — учётная запись и
сводка по клинике. Пароль каждый меняет себе сам.

**Вход в клинику:** сначала выбираете свою клинику → затем email + пароль
(учётная запись выдаётся владельцем/платформой). Данные клиник полностью
изолированы, email уникален в пределах клиники.

## Стек

- **Backend:** Go 1.26, chi, pgx, **sqlc**, golang-migrate, JWT (httpOnly cookie), bcrypt, slog.
- **Frontend:** React + TypeScript + Vite, Tailwind CSS, FullCalendar, TanStack Query, axios.
- **Инфра:** Docker Compose (PostgreSQL 16 + backend, раздающий SPA), миграции при старте.

## Быстрый старт (Docker)

```bash
cp .env.example .env    # поменяйте SUPERADMIN_EMAIL / SUPERADMIN_PASSWORD / JWT_SECRET
docker-compose up --build
```

При первом старте применяются миграции и создаётся администратор платформы из
`SUPERADMIN_EMAIL` / `SUPERADMIN_PASSWORD` (по умолчанию `admin@temart.local` /
`changeme123`). Приложение целиком (SPA + API) доступно на `http://localhost:8080`.

Дальше:
1. Откройте `http://localhost:8080`, нажмите **«Вход для администратора платформы»**,
   войдите кредами superadmin.
2. Создайте клинику и её владельца.
3. Выйдите, выберите клинику и войдите владельцем — управляйте врачами, пациентами и записями.

## Локальная разработка

БД в Docker, backend и frontend — локально:

```bash
docker-compose up -d postgres         # БД на localhost:5433
make run                              # go run ./cmd/server (DATABASE_URL из .env)

cd web && npm install && npm run dev  # http://localhost:5173 (/api → :8080)
```

> Для локальной разработки контейнер `backend` держите остановленным
> (`docker-compose stop backend`) — иначе конфликт по порту 8080.

## Структура

```
cmd/server        — точка входа
internal/config   — конфиг из env
internal/db       — pgx pool, миграции (embed), bootstrap superadmin, sqlc-код
internal/auth     — JWT (+ clinic_id в claims) + bcrypt
internal/middleware — авторизация (cookie), контекст клиники, CORS, логирование
internal/service  — бизнес-логика (проверка пересечений записей)
internal/handlers — HTTP-обработчики (клиника + платформа), роутер, раздача SPA
web/              — фронтенд (React + Vite)
```

## API (основное)

```
GET  /api/clinics                              список активных клиник (для выбора при входе)
POST /api/auth/login                           вход в клинику {clinic_id, email, password}
POST /api/auth/platform/login                  вход администратора платформы {email, password}
POST /api/auth/logout | refresh    GET /api/me

# Платформа (только superadmin)
GET/POST/PUT/DELETE /api/platform/clinics[/:id]
POST /api/platform/clinics/:id/owner           добавить владельца клинике
POST /api/platform/clinics/:id/access          доступ: unlimited | freeze | grant{days}
GET  /api/platform/clinics/:id/users           учётные записи клиники
POST /api/platform/clinics/:id/users/:uid/password   сбросить пароль сотруднику
DELETE /api/platform/clinics/:id/users/:uid    удалить учётную запись клиники
GET/POST/PUT/DELETE /api/platform/admins[/:id] администраторы платформы
POST /api/platform/password                    сменить свой пароль
GET  /api/platform/stats

# Клиника (scoped по clinic_id из токена)
GET/POST/PUT/DELETE /api/appointments[/:id]    (?from&to | ?date, ?doctor_id)
GET/PUT /api/appointments/:id/services         услуги приёма и расчёт стоимости
GET/POST/PUT/DELETE /api/services[/:id]        прайс клиники (владелец/менеджер)
GET /api/stats/revenue                         выручка: день/месяц/год, услуги, врачи
GET  /api/patients?search=&offset=             страница базы (по 20): {items,total}
POST/PUT/DELETE /api/patients[/:id]             GET /api/patients/:id/appointments|records
GET  /api/events?before=<id>                    журнал действий клиники (курсор)
POST /api/me/password                           сменить свой пароль (любая роль)
GET/POST/DELETE /api/patients/:id/avatar        фото пациента
GET/POST/PUT/DELETE /api/doctors[/:id]          GET/PUT /api/doctors/:id/schedule
PUT /api/doctors/:id/profile                    профиль врача (правит он сам)
GET/POST/DELETE /api/doctors/:id/avatar         фото врача
GET/POST/PUT/DELETE /api/users[/:id]            (только владелец клиники)
GET /api/dashboard   GET /api/admin/stats
```

Ответы — JSON; ошибки в формате `{"error": "сообщение"}`.

## Разработка БД

SQL живёт в `internal/db/queries`, типобезопасный Go генерируется через sqlc:

```bash
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
make sqlc          # перегенерировать internal/db/sqlc
make migrate-create name=add_something   # новая пара миграций
```

## Пробный период и доступ клиник

У каждой клиники есть **срок доступа** (`access_expires_at`): NULL — бессрочный,
дата в прошлом — клиника **заморожена**. Суперадмин управляет им при создании
(тумблер «Пробный период» + число дней) и кнопкой **«Доступ»** у клиники:
«Выдать N дней» (продление/разморозка), «Оплачено — доступ навсегда»,
«Заморозить сейчас».

Замороженная клиника: сотрудники могут войти, но видят только экран «Ваш
пробный период истёк» с контактами для продления (WhatsApp +7 777 910 99 65,
tolenn.olzhas@gmail.com). Блокировка настоящая — все рабочие эндпоинты отвечают
403 на сервере (`RequireClinicAccess`), а не только спрятанный интерфейс.
Данные клиники при заморозке не удаляются.

## Тёмная тема

Кнопка с солнышком рядом с логотипом (в сайдбаре и мобильной шапке) переключает
тему: солнце ↔ месяц со звёздочкой. Выбор хранится в `localStorage` и
применяется до первого рендера. Тёмные стили — переопределения ходовых
Tailwind-утилит под `.dark` в `index.css`.

## Общая база пациентов

Карточка пациента и его медицинская история — **общие для всей платформы**:
клиника видит пациентов, заведённых другими клиниками, их приёмы, диагнозы и
снимки. Так база растёт совместно, а пациент не заводится заново в каждой
клинике (дедупликация по ИИН — при совпадении подставляется существующая
карточка).

Приватными остаются **деньги**: услуги, суммы приёмов и выручка привязаны к
клинике и чужим не видны. Менять и удалять можно только своё: **редактировать
карточку пациента (и его фото) вправе лишь клиника, которая её завела** — она же
единственная может её удалить (удаление каскадом уносит приёмы всех клиник).
Чужие приёмы и медзаписи в истории помечены названием клиники.

Список пациентов отдаётся страницами по 20 (`?offset=`) — база общая и растёт,
выгружать её целиком нельзя. Поиск идёт по ФИО, телефону и ИИН по всей платформе.

> Медицинская история пациента видна врачам других клиник — это требует
> согласия пациента на обработку персональных данных.

## Услуги и финансы

- **Прайс** у каждой клиники свой (`Управление → Услуги`). Новой клинике
  автоматически заводятся базовые услуги: удаление зуба 20 000 ₸, лечение
  кариеса 10 000 ₸, пломба 10 000 ₸. Цены — целое число тенге.
- **Расчёт стоимости приёма**: после нажатия «Завершить» открывается окно
  «Услуги и стоимость» — услуги набираются из прайса (или вбиваются разово),
  у каждой позиции своё количество, цена и врач-исполнитель, внизу итог. Вернуться
  к нему можно кнопкой «Услуги и стоимость» в карточке приёма.
- В позицию сохраняется **снимок** названия и цены на момент приёма: изменение
  прайса задним числом не переписывает прошлую выручку, а удаление услуги из
  прайса не портит закрытые приёмы.
- **Финансы** (`Управление → Финансы`): заработок за сегодня / месяц / год / всё
  время, помесячный график за 12 месяцев, разрезы по услугам и по врачам.
  Отменённые приёмы в выручку не входят. Суперадмин видит суммарную выручку всех
  клиник в панели платформы.

## Профиль врача и фотографии

- У пациентов и врачей есть **аватарка** (jpg/png/webp, до 5 МБ). Загружается
  кликом по фото в карточке; без фото показывается инициал, у врача — на его
  цвете из календаря. Старый файл при замене удаляется.
- **Профиль врача** врач ведёт сам в личном кабинете: направление, телефон, дата
  рождения (возраст считается сам), стаж в годах, образование, опыт работы,
  способности и навыки. ФИО, цвет в календаре, активность и привязку к учётной
  записи по-прежнему задаёт владелец — иначе врач мог бы «спрятаться» из
  расписания. Владелец и менеджер могут заполнить профиль за врача из вкладки
  «Врачи» → «Профиль».

## Навигация и календарь

Боковое меню: **Календарь** (выделен — с него начинается рабочий день), Записи,
Пациенты, Врачи, Услуги, раскрывающаяся группа **Управление** (Создать запись,
Пользователи, Статистика, Архив, События) и **Личный кабинет** внизу. Услуги и
Управление видят только владелец и менеджер.

В календаре:
- ось времени подписана полным временем («08:00», а не «8»), часовые линии
  заметные, получасовые — пунктир, суббота и воскресенье подсвечены серым;
- карточку приёма можно **перетащить** на другое время или дату и **растянуть**
  за край, меняя длительность. Врач двигает только свои приёмы, завершённые и
  отменённые не двигаются вовсе. Если врач в это время занят, сервер отвечает
  409 и карточка возвращается на место;
- в карточке приёма есть кнопка **«Завершить»** — администратору сразу
  открывается расчёт стоимости, врачу приём просто закрывается.

Пациент и врач в форме записи выбираются в **боковой шторке с поиском**, а не в
длинном выпадающем списке. Дата и время — тоже шторкой: календарь месяца → день
→ время начала (чипы по полчаса или ручной ввод) → окончание (автоматически
+1 час, правится) → «ОК»; выбранное время и статус показаны в шапке карточки.
Новая запись всегда создаётся со статусом «Запланирован» — селект статусов
появляется только при редактировании. Во вкладке «Записи» вместо фильтра дат —
лента дней месяца (1–31) с переключением месяцев и кнопка «Новая запись».

## События (журнал действий)

`Управление → События` — кто и что сделал: создал, перенёс, отменил или удалил
запись, пробил услуги, завёл или удалил пациента, врача, услугу, учётную запись.
Видят владелец и менеджер. Листается курсором (не смещением), поэтому при
дозагрузке строки не дублируются, даже если в этот момент пишутся новые события.
В записи журнала сохраняется имя сотрудника на момент действия — увольнение и
удаление учётки не делают историю нечитаемой.

## Отмена и удаление записи

Это разные вещи, и в интерфейсе они рядом:

- **Отменить** — приём остаётся в календаре и в истории пациента, помечается
  серым со статусом «Отменён». Так видно, что время было занято.
- **Удалить** — приём стирается насовсем вместе с пробитыми услугами и исчезает
  из календаря. Действие необратимо, поэтому спрашивается подтверждение.

## Режим поддержки

Администратор платформы может открыть данные конкретной клиники, не зная её
пароля: в панели платформы — кнопка **«Открыть»** у клиники. Экраны клиники
(календарь, записи, пациенты, врачи) открываются **только для чтения**: сверху
висит предупреждающая полоса, кнопки изменения скрыты, а сервер отклоняет любой
не-GET запрос в этом режиме (403). Клиника передаётся заголовком
`X-Support-Clinic-Id`, который принимается только у роли `superadmin`. Выход —
кнопка «Вернуться к платформе».

## Замечания

- Данные каждой клиники изолированы: все запросы фильтруются по `clinic_id` из токена.
- `SUPERADMIN_EMAIL` / `SUPERADMIN_PASSWORD` создают **первого** администратора
  платформы при первом старте пустой базы; дальше правка `.env` ничего не меняет —
  администраторы и пароли управляются из панели платформы.
- Все времена хранятся в UTC (`TIMESTAMPTZ`), фронтенд показывает в локальном поясе; даты — в формате ДД.ММ.ГГГГ.
- Один врач не может иметь две пересекающиеся записи — проверка на сервере (HTTP 409).
- Удаление пациента/врача каскадно удаляет связанные приёмы (в UI есть предупреждение).
- В проде задайте сильный `JWT_SECRET` и `COOKIE_SECURE=true` (HTTPS).
